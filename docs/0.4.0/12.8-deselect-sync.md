# 12.8 — Deselection playhead sync (design note)

Written before the code, 2026-10-31. The rule is the author's (bugs-and-fixes,
"Playback and Looping"); the cases are the ones listed in PLAN.md's step 12 analysis.

## Where it lives

`Transport::anchor (doc, next)` is the one place a rolling transport changes its
mapping: a direction change, and the live re-aim `render()` does when the loop's aim
(Set Loop region, else selection, else whole sound) is no longer what it loops. Today it
gives each track one of two phases:

- **keep**: the track was in the old span (`inSpan`) and its frame lies in the new span →
  it goes on reading that frame, heading the way it was;
- **fresh**: anything else → `u = 0`, the new span's start (its end going backward).

Deselecting turns `selection` mode into `all` mode. The tracks outside the old selection
were not in the old span, so they got **fresh** and restarted at 0: the bug.

## The rule

Before re-anchoring, take the **reference R**: the topmost track (lowest index) that the
OLD mapping had reading a frame of its own — `inSpan && present`. Note its frame **F** and
its heading. A track that cannot **keep** then:

1. reads **F** when F lies in its new span, with R's heading;
2. else, in `all` mode, reads **F mod its own length** (a shorter track wraps, so the
   phasing between unequal lengths carries on), with R's heading;
3. else (a `selection` span that does not contain F) or when there is no R: **fresh**, as today.

Heading = backward, or which leg of a ping-pong; forward has only one.

One extra guard: while a take runs (`excludeMask` non-zero) the live re-aim is frozen
altogether (see case 10).

## The 13 cases, settled

| # | Case | Outcome |
|---|---|---|
| 1 | The selected tracks were out of phase with one another | Each selected track keeps its own frame (keep). R (the topmost of them) drives only the tracks that had none. |
| 2 | A formerly-selected track was absent (shorter than its read point) | `present` is false: it cannot be R, and its frame is past its end, so it cannot keep → it follows R. |
| 3 | No R at all (every selected track absent) | fresh, as today. |
| 4 | A new selection over other tracks (`all` → `selection`, or one selection to another) | Same path. A track whose frame is inside the new span keeps it; one that is not takes F if F is inside, else the span's start (backward: its end). |
| 5 | Dragging a selection across tracks re-aims at every step | A track with a frame in the new span keeps it at every step, so nothing that already has a frame jumps; only tracks entering the span pick one up. |
| 6 | A caret | Counts as no selection (`loopAim` already says so): a caret after a selection is a deselection. |
| 7 | Loop with a Set Loop region | The aim is the region; the selection does not change it, so deselecting re-aims nothing. Unchanged. |
| 8 | Loop off (once) | Play-once has no live re-aim: deselecting mid-pass changes nothing until Stop. Unchanged — to tell the author. |
| 9 | Paused | `render()` returns before the re-aim while paused, and `pos` does not move: the re-aim happens on the first block after resume, from the frames the tracks were paused on. |
| 10 | Recording | The Recorder writes from its own counters (the span it snapshotted when the take began), and selections can still be edited mid-take. Re-aiming would make the written tracks' playheads leave the place being written, and a per-track "keep the old phase" cannot help once the span itself changes. So **the live re-aim is frozen while a take runs** (`excludeMask != 0`): the loop keeps the take's aim, and a selection drawn or cleared mid-take re-aims on the first block after the take ends (through this same rule). This extends 9.4's "Loop is read when Record is pressed". To tell the author. |
| 11 | Tracks that were silent come in | `anchor` already starts the ~2 ms crossfade from the old mapping: no click. |
| 12 | Several Windows | Each Window owns its Transport; nothing is shared. |
| 13 | Advance (2×), the Keyboard's rateScale | They scale the step of `pos`; phases are frames, so they are unaffected. |

## Tests (`run_engine.cpp`, `deselectSyncTests`)

One check per case that has behaviour (1–7, 9, 10, 12, 13; 8 asserts "unchanged"),
the playheads the UI reads (`uiTrackPosition`), backward and ping-pong headings, and a
threaded select/deselect stress under TSan.
